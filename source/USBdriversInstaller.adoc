=== USB Drivers Installer

(((Microcontroller Fundamentals,USB Drivers Installer)))


WARNING: Installing the USB driver is only required when using the GCBASIC USB library without `USB_WCID`. With `USB_WCID` defined, Windows 8.1 and later install their own WinUSB driver: see <<_usb_without_a_driver_winusb,USB without a driver (WinUSB)>> below.

*Description:*

The drivers for Windows x86 and x64 correspond to the USB LIBKWIN capability of GCBASIC for supported PIC microcontrollers.

For security reasons, in Microsoft Windows, a driver must be digitally signed by Microsoft in order to be installed.

Microsoft does provide a special "Test" mode for developers to manually install unsigned drivers for debugging and testing, but this is a technically advanced and not user-friendly procedure; at the same time, Windows developers work to disable automated use of this capability, out of concern that it could be used as an operating system vulnerability.

This makes installing test drivers difficult and frustrating for the uninitiated, and for a useful hobby project it is not practical to put end users through all this trouble.

This driver installer method resolves the constraints imposed by the Windows operating system, allowing you to install the drivers in the easiest way possible, much like any driver from a well-known company.

*Usage:*

WARNING: The installer will reboot the system without notice. Please close all programs and save any work you have open before beginning the driver install.

1 - Open the installer; it will request admin rights.

2 - Navigate through the wizard to automatically extract the driver files (there are no options to select).

3 - At the end of the wizard, after you click the exit button, the system will restart automatically.

WARNING: If your computer has Secure Boot enabled, the installer will advise you of extra steps needed after reboot; at the end of this page you will find a graphic showing those steps and which options you need to select.

4 - After restarting and logging in to your user account, a window will inform you that the driver is not signed and ask if you want to install it - please allow it.

5 - When the driver has been installed, the computer will restart automatically.

*USB Driver details*

The driver uses the following USB flags.

[source,gcbasic]
----
    USB_VID 0x1209
    USB_PID 0x2006
    USB_REV 0x0000
----

For other flag values, you need to modify and recompile the USB library.

`USB_PRODUCT_NAME` and `USB_VENDOR_NAME` can be changed without a problem (Windows Device Manager will show the name reported by the hardware, not the driver).

==== USB without a driver (WinUSB)

*Description:*

With `USB_WCID` defined, the USB library answers the Microsoft OS 1.0 descriptor requests that Windows sends to a new device. Windows 8.1 and later then load their own WinUSB driver for the device when it is first plugged in: there is no driver to install, no installer to run and no reboot.

The program is unchanged otherwise: it uses the same vendor requests (`USB_SETUP_HANDLER`, `USBBufferWrite`), and a PC program using LibUsbDotNet, libusb or WinUSB opens the device by its vendor ID and product ID, or by its device interface GUID.

*Enabling Constants:*

[cols="2,4,2", options="header"]
|===
|*Constant*
|*Controls*
|*Default*

|`USB_WCID`
|Define it to answer the Microsoft OS 1.0 descriptor requests (the OS string, the Extended Compat ID "WINUSB" and the Extended Properties).
|Not defined

|`USB_WCID_GUID`
|The device interface GUID, as a string of 38 characters in the form `"{xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx}"`. Required with `USB_WCID`: the compiler stops with an error when it is missing. Give each solution a GUID of its own.
|None

|`USB_WCID_VENDOR_CODE`
|The request code Windows uses to read the descriptors. It must not be one of the program's own request codes.
|`0x20`
|===

*Example:*

[source,gcbasic]
----
    #chip 18F14K50, 48

    #define USB_VID 0x04D8
    #define USB_PID 0x0052
    #define USB_REV 0x0100

    'WinUSB without a driver
    #define USB_WCID
    #define USB_WCID_GUID "{BFC2B144-FB5A-4F56-98AC-93BC164EED46}"

    #define USB_PRODUCT_NAME "GCBASIC WinUSB " + CHIPNAMESTR
    #define USB_SETUP_HANDLER SetupHandler_CallBack

    #include <usb.h>
----

*Notes:*

* Windows asks a device for its Microsoft OS descriptors only once for each vendor ID, product ID and `USB_REV` (bcdDevice), and remembers the answer. A device first plugged in without `USB_WCID` is not asked again until `USB_REV` changes, or until its key under `HKLM\SYSTEM\CurrentControlSet\Control\usbflags\` (vendor ID, product ID and revision as twelve hexadecimal digits) is deleted.
* The vendor ID and product ID are not those of the LibK driver above (`0x1209` / `0x2006`): a PC with that driver installed would use it for the device instead of WinUSB.
* LibUsbDotNet reads the revision from the device's hardware ID as a decimal number: for `USB_REV 0x0100`, search for revision `100`.
* Windows 7 does not read these descriptors: it still needs a driver.
